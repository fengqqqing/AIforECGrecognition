# 数据与模型说明

本文档说明当前公开仓库中的数据、模型文件和实验边界，避免把 Demo 能力误解为临床产品能力。

## 1. 数据范围

公开仓库只保留小体积样例数据：

```text
模型部署pyqt/ECGMonitor/sample_data/test.csv
```

该文件用于离线回放、GUI 展示和部署链路 smoke test。它的作用是让项目在没有串口设备和完整训练数据的情况下仍能运行固定 Demo。

公开仓库不包含完整原始数据集和完整训练/验证/测试 CSV：

```text
artifacts/training/ecg/raw_data/
artifacts/training/ecg/processed_data/
```

如果需要复现实验数据准备流程，应自行取得合法授权的数据来源，并按照原始数据集许可要求使用。

## 2. 模型范围

公开仓库保留部署 Demo 所需的默认 TorchScript 模型：

```text
模型部署pyqt/ECGMonitor/models/best_acc.pt
模型部署pyqt/ECGMonitor/models/best_acc.contract.json
```

`best_acc.contract.json` 是部署侧解释模型输入输出的唯一契约来源，包含：

- 模型文件名。
- 输入窗口长度。
- 输入 shape。
- 归一化方式与参数。
- 输出类别数。
- 标签顺序。

训练侧的 checkpoint、中间模型和历史归档模型不进入公开仓库。

## 3. 评估边界

当前公开 Demo 验证的是工程部署闭环：

```text
样例 ECG 数据 -> 离线回放 -> ECG 处理管线 -> TorchScript 推理 -> PyQt 展示 -> 运行导出
```

真实模型 smoke test 中的 `Diagnosis count: 1` 只表示部署推理链路可用，不代表模型医学准确率达标，也不能替代独立测试集评估。

## 4. 使用边界

- 本项目是 ECG 辅助识别实验系统。
- 模型输出只能作为辅助提示和实验验证结果。
- 不应将本项目直接用于临床独立诊断。
- 不应基于当前 Demo 输出作出真实医疗决策。
- 如进入真实临床场景，必须补齐数据合规、医生复核、权限审计、模型版本追踪和临床验证流程。

## 5. 后续模型更新要求

替换默认模型时，必须同步更新模型契约，并至少审查：

- 新模型文件是否存在且可加载。
- 输入窗口长度是否与部署侧管线一致。
- 归一化参数是否与训练过程一致。
- 输出类别数和标签顺序是否一致。
- 是否记录训练数据版本、checkpoint 来源和测试集指标摘要。

未知信息必须明确标注“当前未记录”，不能补写成未经验证的事实。
