# ECG 自动识别系统 PRD

## 1. 产品概述

本项目旨在构建一个端到端的心电信号（ECG）AI 辅助识别系统。当前阶段重点是算法训练、模型部署和 PyQt 上位机实时推理闭环，系统通过模拟器或离线回放数据获取 ECG 信号，在上位机中展示实时波形，并调用深度学习模型进行多分类识别。

当前产品原型定位为“面向 ECG 采集、初筛和部署验证场景的 AI 辅助桌面工作台”。它的核心价值假设是：在 ECG 采集到医生正式判读之间，为一线非心电专家用户提供信号质量可见、基础状态清楚、AI 辅助提示可读、运行过程可追溯的初筛工作台，降低现场判断、转交和后续复盘成本。

系统输出的 AI 识别结果仅用于辅助提示和实验验证，不能替代医生诊断，也不对外承诺自动临床诊断能力。

## 2. 产品目标

### 2.1 当前 V1 目标

- 建立 ECG 信号采集、实时推理、辅助识别结果展示、运行导出和离线回放的完整闭环。
- 在同一工作台中展示 ECG 波形、导联状态、心率、AI 辅助识别结果和运行指标，支撑正式判读前的信号确认和初筛观察。
- 支持无真实设备时，通过样例数据或最近导出的回放文件验证推理链路。
- 支持真实模型推理结果与源标签的基础对照。
- 为后续模型精度优化、真人临床信号采集和临床产品化演进打基础。

### 2.2 非 V1 目标

- 不做自动临床诊断。
- 不做完整患者管理或病例管理。
- 不接入医院 HIS、EMR、PACS 等系统。
- 不引入独立 Web 后端和数据库。
- 不保存真实患者身份信息。
- 不做临床处置优先级决策或分诊决策。
- 不做 ECG 教学训练、案例库、答案遮罩或学习管理功能。

## 3. 目标用户

| 用户 | 使用目的 |
| --- | --- |
| ECG 采集与初筛人员（核心用户） | 在采集或回放过程中确认波形是否有效、导联是否连接、心率是否可读，并查看正式判读前的 AI 辅助提示。 |
| 基层医生 / 年轻医生 / 值班医生 | 在非心电专科场景下获得结构化辅助提示，识别是否需要优先关注或转交医生复核。 |
| 临床研究人员 | 通过样本回放、结果对照和导出文件复盘模型在不同 ECG 样本上的表现。 |
| 算法 / 部署协作者 | 优化数据处理、模型结构、训练策略、评估指标，并验证模型契约到部署侧的闭环。 |
| 系统测试和项目维护人员 | 使用离线回放、mock 推理和真实模型回放保护核心链路，维护训练侧、部署侧、数据资产和运行产物。 |
| 评审 / 合作 / 决策对象 | 通过 Demo 判断产品场景、解决方案、部署闭环和医学能力边界是否清晰。 |

## 4. 核心功能

### 4.1 ECG 信号采集

- 支持通过串口接收模拟器或设备产生的 ECG 数据。
- 支持导联状态、心率等辅助事件输入。
- 支持串口连接、断开和窗口关闭时的线程安全退出。
- 支持通过波形、导联和心率状态帮助用户判断当前信号是否适合继续观察或转交复核。

### 4.2 实时展示

- 展示实时 ECG 波形。
- 展示心率、导联状态、AI 辅助识别结果和运行指标。
- 运行指标至少包括运行时间、采样点数、诊断次数、单次推理耗时和吞吐量。

### 4.3 AI 推理

- 使用部署侧 TorchScript 模型进行多分类识别。
- 当前模型契约中的输入窗口为 `input.window_size=2000`。
- 推理输出必须映射到稳定的辅助识别标签体系。
- AI 输出用于正式医生判读前的辅助提示，帮助提示是否值得优先关注或复核，不作为最终诊断或处置依据。
- mock 推理仅用于测试，真实模型回放才是模型部署验证重点。

### 4.4 运行导出

- 导出运行指标：`metrics.jsonl`。
- 导出诊断事件：`diagnosis.csv`。
- 导出可回放 ECG 波形：`ecg_replay.csv`。
- 运行产物默认进入 `模型部署pyqt/ECGMonitor/runs/`。

### 4.5 离线回放

- 支持默认样例数据：`模型部署pyqt/ECGMonitor/sample_data/test.csv`。
- 支持最近导出的 `ecg_replay.csv`。
- 支持 mock 推理和真实模型推理。
- 回放输出应展示来源文件、来源行、可用样本数、使用样本数、源标签、推理模式、诊断次数和最近诊断。

### 4.6 结果对照

- 当回放文件存在源标签且使用真实模型推理时，展示源标签、本次诊断和是否一致。
- 当前只做基础一致性对照，不建立完整离线回归样本库。

### 4.7 产品能力分层

当前 V1 功能按产品价值分为四层：

| 能力层 | 当前职责 | 当前能力边界 |
| --- | --- | --- |
| 采集质量保障 | 帮助采集与初筛人员先判断 ECG 是否可观察、导联是否连接、心率是否可读。 | 当前展示波形、导联状态和心率；尚未提供信号质量评分、伪差识别或采集前检查清单。 |
| AI 辅助识别 | 在正式判读前提供结构化辅助提示。 | 当前展示模型分类标签和保守边界文案；不提供最终诊断、处置建议或分诊决策。 |
| 交接与复盘 | 让一次运行留下可追溯证据，便于医生、研究人员或维护者复盘。 | 当前提供最近摘要和导出文件；尚未提供完整交接报告、复盘时间线或医生复核备注。 |
| 部署验证与演示 | 通过固定样例、真实模型回放和检查脚本验证部署链路可运行。 | 当前证明链路可走通；不证明临床准确率或真实场景可用性。 |

## 5. 功能优先级

| 优先级 | 功能 | 说明 |
| --- | --- | --- |
| MVP | 实时采集、波形展示、AI 推理、辅助识别展示 | 当前产品闭环的核心。 |
| MVP | 心率、导联状态和运行状态展示 | 支撑信号质量确认和正式判读前的初筛观察。 |
| MVP | 导出、离线回放、真实模型回放 | 保护无设备验证和模型部署链路。 |
| MVP | 运行指标与最近运行摘要 | 帮助判断系统是否正常工作。 |
| P1 | 信号质量提示 / 采集质量灯 | 进一步回答采集人员最基础的“这张 ECG 能不能看”问题。 |
| P1 | 结构化交接卡 / 运行摘要增强 | 在现有摘要和导出基础上，提升转交复核和复盘效率。 |
| P1 | AI 结果解释边界增强 | 在不承诺临床结论的前提下，让辅助提示更容易被正确理解。 |
| P1 | 训练侧评估体系与模型精度优化 | 当前模型精度仍需提升，应先固化评估基线。 |
| P1 | 文档、目录、命名和乱码清理 | 提升长期可维护性。 |
| P2 | 复盘时间线 | 串联导联、心率、推理和 metrics 事件，增强运行可追溯性。 |
| P2 | ECG 回放训练模块 | 可基于保存和回放能力探索新手医生训练，但需要独立产品设计。 |
| P2 | 真人临床信号采集 | 需要伦理、授权、脱敏和数据质量控制。 |
| P2 | 患者/病例管理 | 需要数据库、权限、审计和医生复核流程。 |
| P2 | 医院系统集成 | 需要独立技术设计和合规评估。 |
| P3 | 医生复核反馈、案例库、模型版本对比 | 价值较高，但依赖权限、数据管理、评估基线和更完整工作流。 |

## 6. 界面设计要求

V1 界面保持桌面上位机风格，优先服务实时监测、初筛观察、离线验证和实验演示。

- 主区域展示 ECG 波形。
- 关键状态区展示 AI 辅助识别结果、心率、导联状态和运行指标。
- 功能入口包括串口设置、开始/停止、离线回放、最近运行摘要和说明。
- 错误提示应明确说明问题来源，例如模型加载失败、回放文件不存在、串口打开失败。
- 识别结果文案必须体现“辅助提示”属性，避免表达成最终临床结论。

## 7. 技术栈建议

当前 V1：

- 前端界面：PyQt5 桌面 GUI。
- 后端逻辑：同进程 Python 模块。
- 模型推理：PyTorch / TorchScript。
- 数据存储：CSV、JSONL、模型文件。
- 测试方式：`unittest`、离线回放、独立 UI smoke check。

未来临床产品化：

- 前端：Web 工作站或医用桌面工作站。
- 后端：Python API 服务和独立推理服务。
- 数据库：PostgreSQL。
- 文件存储：本地文件系统或对象存储。
- 安全能力：权限、审计、脱敏、模型版本追踪和医生复核。

## 8. 代码风格和架构原则

- 训练侧和部署侧通过模型文件衔接，不互相反向依赖。
- GUI 负责展示和调度，不直接承担协议解析、模型加载和导出细节。
- CLI 回放和 GUI 回放必须共用回放源解析逻辑。
- 新增功能优先保持小步增强，避免把无关重构混入功能改动。
- 训练侧优化必须记录数据版本、窗口长度、归一化方式、模型版本和评估指标。
- 部署侧改动必须保护导出、回放、真实模型推理闭环。

## 9. 数据与模型边界

- 部署侧默认模型位于 `模型部署pyqt/ECGMonitor/models/best_acc.pt`。
- 部署侧默认样例数据位于 `模型部署pyqt/ECGMonitor/sample_data/test.csv`。
- 训练侧资产位于 `artifacts/training/ecg/`。
- 运行时导出产物位于 `模型部署pyqt/ECGMonitor/runs/`。
- 当前 V1 不保存真实患者身份信息，不建立临床数据库。
- 标签编号、模型输出类别数、UI 展示标签必须保持一致。
- AI 辅助识别结果必须和模型契约中的标签顺序保持一致，UI 不单独解释模型语义。

## 10. 限制条件和边界场景

当前限制：

- 当前系统尚未达到临床独立诊断产品要求。
- 当前模型精度仍需继续优化。
- 当前自动化测试无法完全覆盖真实串口设备和长时间运行场景。
- 当前文件型存储适合 V1，不适合真实临床多用户场景。
- 当前 AI 辅助提示不能作为临床处置、分诊或最终诊断依据。
- 当前回放能力只用于 Demo、验证和复盘，不提供教学训练模式。

重点边界场景：

- Windows 中文路径下模型加载失败。
- 串口设备断开或数据包异常。
- ECG 样本不足以触发推理窗口。
- 最新回放文件不存在。
- 模型文件缺失或版本不匹配。
- mock 测试通过但真实模型加载失败。
- UI 关闭时 worker 线程未正确退出。

## 11. 验收标准

V1 可接受标准：

- 可以启动 PyQt 上位机主界面。
- 可以通过串口或离线回放接收 ECG 数据。
- ECG 数据累计到 2000 点后可以触发 AI 推理。
- 可以展示 AI 辅助识别结果、心率、导联状态和运行指标。
- 可以导出 `metrics.jsonl`、`diagnosis.csv`、`ecg_replay.csv`。
- 可以使用最新导出的回放文件进行真实模型回放。
- 可以在源标签存在时显示基础结果对照。
- 单元测试、离线回放 smoke test 和 UI smoke check 在相应改动后通过。

## 12. 后续路线

1. 固化当前部署闭环和文档基线。
2. 围绕采集质量保障补强信号质量提示、采集质量灯和运行摘要。
3. 增强结构化交接和复盘能力，例如交接卡、复盘时间线和报告模板。
4. 建立训练侧稳定评估基线，再围绕类别不均衡、窗口一致性、归一化一致性和模型结构逐步提升精度。
5. 补齐真实临床采集前的数据授权、脱敏、质量控制和医生确认流程。
6. 基于保存和回放能力，独立评估 ECG 教学训练 / 新手医生练习模块的用户场景、案例库、答案遮罩、反馈和学习记录设计。
7. 在真实临床产品化前，再单独设计数据库、后端服务、权限审计、医生复核和模型版本管理。
