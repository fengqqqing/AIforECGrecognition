# ECG 自动识别系统 PRD

## 1. 产品概述

本项目旨在构建一个端到端的心电信号（ECG）自动识别系统。当前阶段重点是算法训练、模型部署和 PyQt 上位机实时推理闭环，系统通过模拟器或离线回放数据获取 ECG 信号，在上位机中展示实时波形，并调用深度学习模型进行多分类识别。

产品定位是“医生辅助识别工具”。系统输出的 AI 诊断结果仅用于辅助提示和实验验证，不能替代医生诊断，也不对外承诺自动临床诊断能力。

## 2. 产品目标

### 2.1 当前 V1 目标

- 建立 ECG 信号采集、实时推理、结果展示、运行导出和离线回放的完整闭环。
- 支持无真实设备时，通过样例数据或最近导出的回放文件验证推理链路。
- 支持真实模型推理结果与源标签的基础对照。
- 为后续模型精度优化、真人临床信号采集和临床产品化演进打基础。

### 2.2 非 V1 目标

- 不做自动临床诊断。
- 不做完整患者管理或病例管理。
- 不接入医院 HIS、EMR、PACS 等系统。
- 不引入独立 Web 后端和数据库。
- 不保存真实患者身份信息。

## 3. 目标用户

| 用户 | 使用目的 |
| --- | --- |
| 临床医生 | 查看 ECG 波形、心率、导联状态和模型辅助识别结果。 |
| 临床研究人员 | 通过样本回放和结果对照验证模型在不同 ECG 样本上的表现。 |
| 算法开发人员 | 优化数据处理、模型结构、训练策略和评估指标。 |
| 系统测试人员 | 使用离线回放、mock 推理和真实模型回放保护核心链路。 |
| 项目维护人员 | 按文档边界维护训练侧、部署侧、数据资产和运行产物。 |

## 4. 核心功能

### 4.1 ECG 信号采集

- 支持通过串口接收模拟器或设备产生的 ECG 数据。
- 支持导联状态、心率等辅助事件输入。
- 支持串口连接、断开和窗口关闭时的线程安全退出。

### 4.2 实时展示

- 展示实时 ECG 波形。
- 展示心率、导联状态、AI 诊断结果和运行指标。
- 运行指标至少包括运行时间、采样点数、诊断次数、单次推理耗时和吞吐量。

### 4.3 AI 推理

- 使用部署侧 TorchScript 模型进行多分类识别。
- 当前模型契约中的输入窗口为 `input.window_size=2000`。
- 推理输出必须映射到稳定的诊断标签体系。
- mock 推理仅用于测试，真实模型回放才是模型部署验证重点。

### 4.4 运行导出

- 导出运行指标：`metrics.jsonl`。
- 导出诊断事件：`diagnosis.csv`。
- 导出可回放 ECG 波形：`ecg_replay.csv`。
- 运行产物默认进入 `模型部署pyqt/ECGMonitor/runs/`。

### 4.5 离线回放

- 支持默认样例数据：`模型部署pyqt/ECGMonitor/sample_data/test.csv`。
- 支持最近导出的 `ecg_replay.csv`。
- 支持 mock 推理和真实模型推理。
- 回放输出应展示来源文件、来源行、可用样本数、使用样本数、源标签、推理模式、诊断次数和最近诊断。

### 4.6 结果对照

- 当回放文件存在源标签且使用真实模型推理时，展示源标签、本次诊断和是否一致。
- 当前只做基础一致性对照，不建立完整离线回归样本库。

## 5. 功能优先级

| 优先级 | 功能 | 说明 |
| --- | --- | --- |
| MVP | 实时采集、波形展示、AI 推理、诊断展示 | 当前产品闭环的核心。 |
| MVP | 导出、离线回放、真实模型回放 | 保护无设备验证和模型部署链路。 |
| MVP | 运行指标与最近运行摘要 | 帮助判断系统是否正常工作。 |
| P1 | 训练侧评估体系与模型精度优化 | 当前模型精度仍需提升，应先固化评估基线。 |
| P1 | 文档、目录、命名和乱码清理 | 提升长期可维护性。 |
| P2 | 真人临床信号采集 | 需要伦理、授权、脱敏和数据质量控制。 |
| P2 | 患者/病例管理 | 需要数据库、权限、审计和医生复核流程。 |
| P2 | 医院系统集成 | 需要独立技术设计和合规评估。 |

## 6. 界面设计要求

V1 界面保持桌面上位机风格，优先服务实时监测、离线验证和实验演示。

- 主区域展示 ECG 波形。
- 关键状态区展示诊断结果、心率、导联状态和运行指标。
- 功能入口包括串口设置、开始/停止、离线回放、最近运行摘要和说明。
- 错误提示应明确说明问题来源，例如模型加载失败、回放文件不存在、串口打开失败。
- 诊断文案必须体现“辅助提示”属性，避免表达成最终临床结论。

## 7. 技术栈建议

当前 V1：

- 前端界面：PyQt5 桌面 GUI。
- 后端逻辑：同进程 Python 模块。
- 模型推理：PyTorch / TorchScript。
- 数据存储：CSV、JSONL、模型文件。
- 测试方式：`unittest`、离线回放、独立 UI smoke check。

未来临床产品化：

- 前端：Web 工作站或医用桌面工作站。
- 后端：Python API 服务和独立推理服务。
- 数据库：PostgreSQL。
- 文件存储：本地文件系统或对象存储。
- 安全能力：权限、审计、脱敏、模型版本追踪和医生复核。

## 8. 代码风格和架构原则

- 训练侧和部署侧通过模型文件衔接，不互相反向依赖。
- GUI 负责展示和调度，不直接承担协议解析、模型加载和导出细节。
- CLI 回放和 GUI 回放必须共用回放源解析逻辑。
- 新增功能优先保持小步增强，避免把无关重构混入功能改动。
- 训练侧优化必须记录数据版本、窗口长度、归一化方式、模型版本和评估指标。
- 部署侧改动必须保护导出、回放、真实模型推理闭环。

## 9. 数据与模型边界

- 部署侧默认模型位于 `模型部署pyqt/ECGMonitor/models/best_acc.pt`。
- 部署侧默认样例数据位于 `模型部署pyqt/ECGMonitor/sample_data/test.csv`。
- 训练侧资产位于 `artifacts/training/ecg/`。
- 运行时导出产物位于 `模型部署pyqt/ECGMonitor/runs/`。
- 当前 V1 不保存真实患者身份信息，不建立临床数据库。
- 标签编号、模型输出类别数、UI 展示标签必须保持一致。

## 10. 限制条件和边界场景

当前限制：

- 当前系统尚未达到临床独立诊断产品要求。
- 当前模型精度仍需继续优化。
- 当前自动化测试无法完全覆盖真实串口设备和长时间运行场景。
- 当前文件型存储适合 V1，不适合真实临床多用户场景。

重点边界场景：

- Windows 中文路径下模型加载失败。
- 串口设备断开或数据包异常。
- ECG 样本不足以触发推理窗口。
- 最新回放文件不存在。
- 模型文件缺失或版本不匹配。
- mock 测试通过但真实模型加载失败。
- UI 关闭时 worker 线程未正确退出。

## 11. 验收标准

V1 可接受标准：

- 可以启动 PyQt 上位机主界面。
- 可以通过串口或离线回放接收 ECG 数据。
- ECG 数据累计到 2000 点后可以触发 AI 推理。
- 可以展示诊断结果、心率、导联状态和运行指标。
- 可以导出 `metrics.jsonl`、`diagnosis.csv`、`ecg_replay.csv`。
- 可以使用最新导出的回放文件进行真实模型回放。
- 可以在源标签存在时显示基础结果对照。
- 单元测试、离线回放 smoke test 和 UI smoke check 在相应改动后通过。

## 12. 后续路线

1. 固化当前部署闭环和文档基线。
2. 建立训练侧稳定评估基线。
3. 围绕类别不均衡、窗口一致性、归一化一致性和模型结构逐步提升精度。
4. 补齐真实临床采集前的数据授权、脱敏、质量控制和医生确认流程。
5. 在真实临床产品化前，再单独设计数据库、后端服务、权限审计和模型版本管理。
