# UI 重塑说明

本文档定义“展示型 UI 优化阶段”的视觉契约和验收边界。当前目标是把 PyQt 上位机主界面从原始控件堆叠改造成一个可用于求职展示的 ECG AI 工作台，同时保护现有模型、回放、导出和测试闭环。

## 1. 阶段目标

本轮 UI 重塑服务于 demo 展示和面试讲述，重点回答三个问题：

- 第一眼能看出这是 ECG 监测与 AI 辅助识别工作台。
- 展示者能清楚指向波形、心率、导联、辅助识别结果、运行指标和导出闭环。
- 视觉体验明显区别于当前原始黑底控件布局，但不改变任何 ECG 数据流、模型语义或 demo policy。

本轮不以临床产品化为目标，不把界面包装成真实医院工作站，也不承诺医学准确率。

## 2. 视觉方向

风格关键词：

- 专业监测感：ECG 波形是第一视觉重点，界面应像实时监测工作台，而不是普通表单。
- 工程可信感：运行指标、demo 状态和导出入口要清楚，让闭环能力可被讲述。
- 克制医疗感：使用“AI 辅助识别”“辅助提示”等文案，不使用“最终诊断”“临床诊断结论”等表达。
- 稳定可读：避免过强装饰和复杂动效，优先保证演示时文本、数值和波形清晰。
- 桌面应用一致性：保留 PyQt 桌面上位机属性，不引入 Web 化导航、患者档案页或后台管理式结构。

建议视觉基调：

- 深色监测背景承载 ECG 波形，使用低对比网格和高亮波形色。
- 信息卡片使用浅色或低饱和深色块，保持层级清楚。
- 正常、异常、未知状态使用稳定色彩语义，不用大面积警示色制造误解。
- 字体优先使用系统可用字体，减少依赖装饰字体，保证 Windows 中文路径和不同机器上的显示稳定。

## 3. 信息架构

主界面应重排为四个展示区域：

1. 顶部标题与模式区
   - 显示项目名或工作台标题。
   - 显示当前模式：Demo、离线回放或串口采集。
   - 保留主要操作入口，例如离线回放、最近运行摘要、打开导出目录、重置显示。

2. 中央 ECG 波形区
   - 作为最大区域展示实时 ECG 波形。
   - 波形背景、边框和网格由统一主题控制。
   - 不改变 `mECG1WaveList`、绘制触发频率、窗口累计或推理触发逻辑。

3. 右侧识别与生命体征区
   - AI 辅助识别结果作为核心结果卡片展示。
   - 心率显示为大数字卡片。
   - 导联状态显示为状态徽标或小卡片。
   - 文案保持“辅助识别/辅助提示”边界。

4. 底部运行指标与状态区
   - 展示推理次数、单次推理耗时、吞吐量、包计数等工程指标。
   - 保留状态栏用于错误、demo 运行状态和摘要提示。
   - 不改变 `WorkerMetrics` 字段语义，也不改变导出文件结构。

## 4. 控件契约

后续 UI 重排可以移动控件、调整尺寸、调整样式，但必须保留以下对象名和业务含义：

| 控件对象名 | 当前职责 | 重塑要求 |
| --- | --- | --- |
| `ecg1WaveLabel` | 承载 ECG 波形 `QPixmap` | 必须保留为波形绘制目标，可放大和重新设样式。 |
| `heartRateLabel` | 显示心率数值 | `on_heart_rate(72)` 仍显示 `72`，无效心率仍显示 `--`。 |
| `heartRateTextLabel_2` | 显示导联连接状态文字 | `on_lead_status()` 后文案仍由 `ui_rules.py` 控制。 |
| `connectStateLabel_2` | 显示 AI 辅助识别结果 | `on_diagnosis(0)` 后仍显示模型契约标签中的“正常”。 |
| `connectStateLabel` | 导联脱落图标 | 可调整呈现方式，但不能破坏导联脱落状态显示。 |
| `connectStateLabel_5` | 导联连接图标 | 可调整呈现方式，但不能破坏导联连接状态显示。 |
| `metricsLabel` | 状态栏运行指标文本 | 可迁移到更醒目的指标区，但原指标语义不能丢失。 |

菜单动作可以改成按钮或保留菜单，但必须复用已有 slot，不新建绕过现有流程的数据入口。

## 5. 颜色与字体方向

推荐颜色语义：

| 语义 | 建议方向 | 用途 |
| --- | --- | --- |
| 主背景 | 接近黑色或深灰蓝 | 监测工作台背景。 |
| 波形背景 | 深色 | ECG 主视觉区域。 |
| 波形线 | 高亮绿色或青绿色 | 实时 ECG 线条。 |
| 网格线 | 低透明度灰绿或灰蓝 | 辅助读波形，不抢主视觉。 |
| 正常状态 | 绿色 | 正常、导联连接、运行正常。 |
| 警示状态 | 红色或橙红色 | 导联脱落、错误、模型/回放失败。 |
| 未知/未开始 | 灰色 | 未开始、未知、无结果。 |
| 卡片背景 | 深灰或浅灰白 | 结果、心率和指标分区。 |

字体方向：

- 主标题使用清晰无衬线字体，避免过度装饰。
- 数字类信息如心率、推理耗时和吞吐量应比说明文字更醒目。
- 中文说明文字保持短句，避免在小卡片中换行拥挤。
- 不使用依赖特定机器才有的艺术字体作为核心信息字体。

## 6. 禁止事项

本轮 UI 重塑禁止做以下事情：

- 不修改模型文件、模型契约格式、标签顺序或分类数量。
- 不修改 `DEMO_REPLAY_POLICY`、样例数据内容或固定 demo 场景。
- 不修改 `EcgProcessingPipeline` 的推理触发、事件处理和 metrics 产生逻辑。
- 不改变 `RunExporter` 的导出文件结构和字段语义。
- 不新增 Web、数据库、患者管理、医生复核或医院系统集成能力。
- 不把 mock 推理描述成真实模型能力。
- 不把真实模型 smoke 描述成医学准确率验证。
- 不把 AI 结果写成最终临床诊断结论。
- 不删除关键控件对象名以换取布局自由。
- 不把大量业务判断写进 `.ui` 或自动生成的 `ParamMonitor_ui.py`。

## 7. 验收标准

视觉验收：

- 启动后第一屏能明确看出 ECG 波形是主视觉中心。
- 主界面结构与当前原始黑底控件堆叠有明显差异。
- AI 辅助识别、心率、导联状态和运行指标有清晰分区。
- Demo 模式、离线回放状态和主要操作入口一眼可见。
- 文案保持辅助识别边界，没有夸大临床能力。

行为验收：

- `python main.py` 普通启动行为保持不变。
- `python main.py --demo` 仍可自动进入固定 demo 回放。
- `on_diagnosis(0)` 后仍显示“正常”。
- `on_heart_rate(72)` 后仍显示 `72`，`on_heart_rate(0)` 后仍显示 `--`。
- `on_lead_status(0)` 和 `on_lead_status(1)` 的导联文案正确。
- `on_metrics_updated()` 后核心指标仍能显示。
- 最近运行摘要、打开导出目录和重置显示入口仍可用。

回归验收：

- UI smoke check 可通过。
- `run_demo_checks.ps1` 可通过。
- 固定 demo mock 回放和真实模型回放都能完成至少一次诊断。
- 不出现 `QThread: Destroyed while thread is still running`。

## 8. 审查重点

审查时优先确认以下问题：

- 视觉改动是否集中在展示层，没有夹带模型、管线和导出语义变更。
- 控件对象名和业务含义是否被保留。
- 文案是否始终使用“辅助识别/辅助提示”口径。
- 新增主题或样式是否集中管理，避免样式散落在业务逻辑里。
- 指标展示是否帮助说明工程闭环，而不是堆满难以阅读的信息。
- README 和 Demo runbook 后续更新是否真实反映当前能力。

当前 UI 结构事实：

- 主窗口来自 `ParamMonitor_ui.ui` / `ParamMonitor_ui.py`，当前使用固定几何布局。
- 当前主窗口初始尺寸约为 `785 x 324`，整体空间偏紧。

当前视觉问题清单：

- ECG 波形区域高度偏小，第一眼不够像监测工作台。
- 心率、导联状态和 AI 辅助识别结果在同一个黑底区域内并列，层级不清。
- 结果区只显示标签，缺少“辅助提示”边界说明。
- 运行指标挤在状态栏，面试讲述时不够醒目。
- 当前界面大量使用纯黑背景和局部高饱和红绿文字，状态语义可读但视觉层次较粗。
- 部分字体使用装饰性中文字体，跨机器稳定性和专业感不足。
- 主操作入口在菜单中，demo 展示时不如可见按钮直观。

## 11. 右侧布局稳定性契约

本轮布局修正后，右侧信息区采用“三卡结构 + 滚动兜底”：

1. `AI 辅助识别卡`
   - 保留 `connectStateLabel_2` 和 `assistantHintLabel`。
   - 只表达模型辅助识别结果，不写成临床诊断结论。

2. `心率卡`
   - 保留 `heartRateLabel` 和 `heartRateUnitLabel`。
   - 心率数值使用文本型指标样式，不使用额外背景块，避免在紧凑右栏中显得突兀或被裁切。
   - 心率数值与 `bpm` 使用接近或一致的字号，并保持同一行基线对齐。

3. `导联状态卡`
   - 保留 `heartRateTextLabel_2`、`connectStateLabel_5`、`connectStateLabel`、`leadStructureLabel` 等关键对象名。
   - 继续表达三导联单通道采集和导联连接/脱落状态，不展示 12 导联矩阵。

4. `rightInfoScrollArea` 兜底
   - 正常展示尺寸下不应出现明显滚动感。
   - 极端高度、字体缩放或 DPI 差异下，右侧内容允许内部滚动，不允许被父容器直接裁切。

布局验证矩阵覆盖：

- 窗口尺寸：`1024x600`、`1280x720`、本机全屏近似尺寸、`1920x1080`、`2560x1440`。
- 模式状态：串口待机、Demo 运行中、离线回放已完成。
- 导联状态：未知、连接、脱落。
- 心率状态：`--`、正常心率、高心率展示值。
- 指标状态：空值、普通值、较长值。

后续维护原则：

- 不通过反复增减单个 `fixedHeight` 修复裁切问题。
- 先判断顶部、主内容、底部三段的高度预算，再调整局部控件。
- 右侧维持 `AI / 心率 / 导联状态` 三张语义清晰的顶层卡片，滚动区只作为极端尺寸兜底。
- 测试应保护“不重叠、不裁切、关键控件可见或可滚动访问”，不绑定具体像素外观。

## 12. 波形视觉适配记录

当前 ECG 波形绘制包含独立的视觉居中适配：显示层会基于当前窗口样本的中位数更新平滑 baseline，再把 ECG 原始值映射到波形区域中线附近。

该逻辑只影响屏幕上的波形垂直位置和观感，不改变以下内容：

- ECG 样本原始值。
- 推理窗口累计与触发条件。
- 模型输入、模型输出和诊断类别。
- 离线回放、metrics、导出文件语义。

后续如果继续调整波形缩放或 baseline，应作为“波形自适应显示”单独评审，并配套真实 demo 回放截图或视觉验收，不应混入右侧信息栏布局修复。
